## 0. Как читать макет

`web-mockup.dc.html` — **референс дизайна, не код для копирования**
(формат дизайн-холста: инлайн-стили, `<sc-if>`/`<sc-for>`, класс
`Component` с `renderVals()`). Из него брать: точные цвета обеих тем
(строка `vars` в `renderVals`), размеры, радиусы, отступы, структуру
экранов, тексты и поведение кнопок (обработчики в `renderVals`). Данные
(компании, имена, суммы, «≈ $1,90») — **вымышленные**, `[в скобках]` —
заглушки. Живой макет у владельца: claude.ai/artifact/TpoGx716yYRWvnWrU9YSmt
(приватный, у тебя доступа нет).

В макете нарисованы: **Пульт**, **Задачи** (список/канбан + боковая
карточка), **Почта → Разбор**, **панель агента** справа с контекстом.
Остальные пункты меню в макете показывают тост «не нарисовано» — их
внешний вид меняется только за счёт общих токенов и компонентов (W1).

## 2. Правила

- Соглашения репозитория (`CURRENT_STATE.md`, `apps/web/CLAUDE.md`):
  комментарии на русском с «почему»; права проверяет сервер, UI только
  не показывает недоступное; мутации — с `Idempotency-Key`, где API их
  требует; безопасные коды ошибок; «LLM — не граница безопасности».
- Иконки — `lucide-react`. Шрифты не менять (Onest + JetBrains Mono).
- Никаких действий от имени пользователя без его подтверждения: отправка
  письма, архив, массовые изменения — через существующий механизм
  одобрения (планы действий), не напрямую.
- Доступность: настоящие `<button>`/`<a>`, `aria-label` у кнопок-иконок,
  видимый фокус, контраст ≥ 4.5:1 (значения из макета проходят),
  горячие клавиши не перехватывают ввод в полях.
- Адаптивность: при ширине < 1100px правая колонка (агент/карточка)
  становится выезжающей панелью поверх контента; < 760px меню
  сворачивается в бургер. Макет показывает desktop 1440.
- Проверка каждого этапа: `npx tsc --noEmit`, `npm run build` в
  `apps/web`, тесты API (`npm run test --workspace=apps/api`), если API
  менялся; ширины 1440 / 1280 / 1024 / 390, обе темы.

### 4.2 Панель агента (`components/agent-panel/*`) — главное изменение
- Одна панель вместо отдельной страницы ассистента в повседневной работе.
  Открывается кнопкой «Агент» в шапке любой страницы, кнопкой в меню и
  `Ctrl+K` (`Cmd+K` на Mac; не перехватывать, если фокус в поле ввода
  кроме самой панели). Состояние открыта/закрыта — в `localStorage`.
  Страница `/assistant` остаётся как полноэкранный режим той же панели
  (общий код, кнопка «развернуть»).
- **Контекст**: страница сообщает панели, на что смотрит пользователь —
  `{ kind: 'dashboard' } | { kind: 'task', id } | { kind: 'mail', id } |
  { kind: 'event', id } | { kind: 'meeting', id } | { kind: 'list', route, filter }`
  (React-контекст `AgentContextProvider`, страницы вызывают
  `useAgentContext(...)`). В шапке панели чип «Контекст: Задача: …».
- Передача контекста на сервер: новое необязательное поле
  `context: { kind, id? }` в DTO отправки сообщения
  (`messages` и `messages/stream`). Сервер **сам** загружает сущность с
  проверкой прав пользователя (тот же сервис, что у раздела) и добавляет в
  текущий user-turn блок `[page_context]…[/page_context]` с краткой
  сводкой (как уже сделано для `[live_context]`), добавляет его в
  `stripLeakedContextMarkers`. id из клиента — только подсказка: нет прав
  или сущности — контекст молча не добавляется. Тесты: чужая задача не
  попадает в контекст; маркер не утекает в ответ.
- **Чипы-подсказки** над полем зависят от контекста (макет: Пульт —
  `/день /к-встрече /просрочки /итоги-недели`; задача — «Напомнить
  исполнителю», «Почему просрочено?», «Перенести на четверг»; письмо —
  «Короче», «Официальнее», «Добавь срок до пятницы», «Поручить …»). До
  появления навыков (ARMS фаза 3) чипы со слешем отправляют обычный текст
  («Что важно сегодня?» и т.п.), чип модели под ответом не показывать.
- Ответы агента, меняющие данные (перенос срока, задача из письма), —
  только через существующие пишущие инструменты/планы с подтверждением.
  В макете агент пишет «подтвердите в карточке» — так и должно быть.
- Голосовой ввод: кнопка справа от поля — микрофон, если поле пустое
  (существующий голосовой поток из `assistant/page.tsx`), иначе «отправить».
- **Агенты календаря и почты** (`calendar-agent.tsx`, `mail-agent.tsx`)
  в W5 не удалять — оставить вкладки, но добавить в панель агента
  возможность открыть их план действий ссылкой; объединение логики — за

### 4.5 Почта → Разбор (`app/mail/page.tsx`)
- Новая первая вкладка **«Разбор»** (остальные: Все письма, Дайджесты,
  Планы действий — бывшая вкладка агента).
- Слева очередь: письма с `needsReply = true` или `needsAction = true`,
  сортировка по важности и возрасту; точка важности, тема, отправитель,
  тег (ОТВЕТ / ДЕЙСТВИЕ / ИНФО); обработанные — зачёркнуты с итогом.
- Справа текущее письмо: чип важности, «2 дня · 1 из 6», тема 21px,
  отправитель, блок **«Суть»** (`EmailAnalysis.summary`/`actionSummary`),
  вложения чипами, поле **«Черновик ответа»** (редактируемое) и кнопки
  **Отправить** (акцент) / **Поручить → задача** / **Позже** / **В архив**.
  После действия — следующее необработанное письмо; в конце «Почта
  разобрана» со сводкой.
- Бэкенд (детерминированно, без разбора свободного текста):
  - `POST /mail/messages/:id/draft-reply` — черновик ответа (Haiku; когда
    появится навык `/тон` из ARMS фазы 3 — с ним), сохраняется в
    `MailDraft` (`sourceMessageId`), повторный вызов возвращает
    сохранённый, `?regenerate=true` — новый. Черновик готовится заранее
    фоновой задачей для писем очереди, чтобы разбор не ждал модель.
  - `POST /mail/messages/:id/actions` `{ type: 'SEND_REPLY' | 'CREATE_TASK'
    | 'ARCHIVE', draftId?, draftText?, task?: {title, assigneeId?, dueDate?} }`
    — создаёт план действий из **одного** пункта нужного типа (без LLM) в
    существующем механизме `mail/action` и возвращает его для одобрения.
    UI сразу показывает подтверждение «Отправить ответ на … ?» и после
    «Да» вызывает существующий `approve`; выполнение — существующий
    исполнитель. `Idempotency-Key` обязателен.
  - «Позже» — `snoozedUntil` на письме (новое nullable поле в
    `EmailAnalysis` или отдельная таблица), письмо возвращается в очередь
    на следующий рабочий день в 9:00 местного времени.
  - Права и почтовый ящик — как у существующих эндпоинтов почты
    (включая `X-Act-As: leader` для ADMIN).
- Клавиши: J/K — письма, Ctrl+Enter — отправить (с подтверждением),
  T — поручить, L — позже, A — архив.
